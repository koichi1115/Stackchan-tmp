# 書き込み前のバックアップ手順（必須）

非公式ファームウェアを書き込むと、純正ファームウェアは失われます。**書き込みの前に必ずこの手順でバックアップを取り、成功行が出るまで書き込みへ進まないでください。** バックアップが取れていれば、[`../scripts/restore-device.sh`](../scripts/restore-device.sh) でいつでも純正状態へ戻せます。

この手順は**所有者が自分の PC で、ロボットを USB でつないだ状態**で実行します。クラウド上や CI では実行できません。

## この手順が守ること

- フラッシュ容量とチップ種別を**仮定せず** `esptool` の `flash_id` で実測します。
- フラッシュ全体をオフセット 0 から実測容量ぶんだけ吸い出します。
- パーティションテーブル領域を**別ファイルとして**吸い出し、全体ダンプの同じ範囲と一致することを確認します。
- **2 回読み出し、SHA-256 が一致した場合だけ**バックアップを有効と判定します。
- ダンプ長が実測容量と一致しない場合は失敗として中止します。
- 純正ファームウェアのバージョン文字列と起動バナーをバックアップ先へ記録します。
- **消去は一切行いません。** `erase_flash` はこのリポジトリのどのスクリプトにも含まれていません。

## 準備

1. Python 3 と `esptool` を用意します。

   ```sh
   pip install esptool
   ```

   起動バナーも記録したい場合は `pyserial` も入れてください（`pip install pyserial`）。無くてもバックアップ自体は成立します。

2. ロボットを USB でつなぎ、シリアルポート名を確認します。

   ```sh
   ls /dev/ttyUSB* /dev/ttyACM*   # Linux
   ls /dev/cu.usb*                # macOS
   ```

3. 途中で USB が抜けないようにします。全体読み出しは容量に応じて数分かかります。

## バックアップの実行

```sh
./scripts/backup-device.sh --port /dev/ttyUSB0
```

出力先は `backups/<UTC タイムスタンプ>/` です。`backups/` は Git 管理外です。

```
backups/20260909T101500Z/
├── SHA256SUMS            # full-flash.bin と partition-table.bin のハッシュ
├── boot-banner.txt       # 起動時のシリアル出力
├── chip-info.txt         # flash_id の生出力（チップ種別・フラッシュ容量・MAC）
├── esptool-version.txt
├── firmware-version.txt  # 純正ファームウェアのプロジェクト名・バージョン・IDF 版
├── full-flash.bin        # フラッシュ全体
├── manifest.txt          # 実測値と SHA-256 の要約
├── partition-table.bin   # パーティションテーブル領域の個別ダンプ
├── partition-table.txt   # 上を人が読める形に展開したもの
└── read-*.log
```

### 成功行

最後に次の行が出たときだけ、バックアップは有効です。

```
バックアップ成功。2 回の読み出しが SHA-256 で一致しました。書き込みへ進んで構いません。
```

**この行が出ていない場合、書き込みへ進まないでください。** 途中で中止した場合、`full-flash.bin` は不完全な可能性があります。原因（USB ケーブル、ボーレート、給電）を直してから最初からやり直してください。ボーレートを下げると安定することがあります。

```sh
./scripts/backup-device.sh --port /dev/ttyUSB0 --baud 115200
```

### 実測値の転記

`chip-info.txt` に出たチップ種別とフラッシュ容量を [`real-device-path.md`](real-device-path.md) の表へ転記し、[M5Stack 製品マニュアル](https://docs.m5stack.com/en/StackChan)の記載と一致することを確認してください。ここが一致しない状態では書き込みへ進まないでください。

### バックアップの保管

`full-flash.bin` はフラッシュの完全な複製です。Wi-Fi 資格情報や端末固有の情報を含む可能性があります。**Git へ入れず、公開せず、手元の安全な場所に保管してください。** 別ドライブへもう一部複製し、`manifest.txt` の SHA-256 を控えておくことを勧めます。

## 書き込み手順との関係

書き込みの具体的な手順は [`../firmware/README.md`](../firmware/README.md) にあります。順序は次のとおりで、入れ替えてはいけません。

1. このページの手順でバックアップを取る。
2. 成功行を確認する。
3. `full-flash.bin` を別ドライブへ複製する。
4. その後で初めて `firmware/README.md` の書き込み手順へ進む。

## 復元の手順

純正ファームウェアへ戻すときは次を実行します。

```sh
./scripts/restore-device.sh --port /dev/ttyUSB0 --backup-dir backups/20260909T101500Z
```

スクリプトは次の順で確認します。

1. `SHA256SUMS` と `manifest.txt` に対してバックアップの SHA-256 とサイズを検証する。
2. つないでいる実機のチップ種別とフラッシュ容量がバックアップ時と一致することを確認する。
3. `RESTORE` と入力させて確認する（`--yes` で省略可）。
4. オフセット 0 へ `--flash_size keep` で書き戻す（ヘッダーを書き換えず、原本どおりに戻すため）。
5. 同じ長さを読み返し、SHA-256 がバックアップと一致することを確認する。

いずれかで不一致があれば中止し、書き戻し後の照合で失敗した場合は「電源を切らずにもう一度実行する」よう促します。消去は行いません。

### 復元チェックリスト

- [ ] `backups/<タイムスタンプ>/` に `full-flash.bin`、`SHA256SUMS`、`manifest.txt` が揃っている。
- [ ] ロボットが USB でつながっており、ポート名が分かっている。
- [ ] `restore-device.sh` が「チップ」「フラッシュ容量」の一致確認を通過した。
- [ ] 確認プロンプトで `RESTORE` と入力した。
- [ ] 最後に「復元成功。SHA-256 は … です。」が表示された。
- [ ] ロボットを再起動し、純正の画面と音声が戻ったことを目視・耳で確認した。
- [ ] 純正に戻した後は、リレーの `RELAY_HOST` を実機用のアドレスから戻すか、そのままにするかを判断した（純正では実機は接続してきません）。

## スクリプトの検証状況

フラッシュ容量表記の解釈、パーティションテーブルの走査、アプリ記述子の読み取りは [`../scripts/flash_tools.py`](../scripts/flash_tools.py) に分離してあり、合成イメージに対する単体テスト（`tests/test_flash_tools.py`、`./scripts/test-all.sh` に含まれます）で確認済みです。

一方で、**`esptool` を呼び出す部分は実機が無いと実行できないため、まだ一度も動かしていません。** 最初の実行では、成功行が出るかどうかを特に注意して確認してください。

## 失敗したときに触ってはいけないこと

- `esptool erase_flash` は実行しないでください。この手順のどこでも必要ありません。
- バックアップが取れていない状態で書き込みを始めないでください。純正ファームウェアの再配布は保証されていません。
- `full-flash.bin` を編集しないでください。復元は原本どおりのバイト列でのみ成立します。
